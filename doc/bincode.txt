Brainfunk bincode: 32-bit instruction encoding
==============================================

doc/bitcode.txt defines what each instruction does.  "Program images", at the end, describes
the forms a whole program takes: a listing, hexadecimal text, and image files.

Opcodes
-------

X    0   NONE
A    1   DATA
S    2   DATA
MUL  3   MUL
F    4   SCAN
M    5   MOVE
JE   6   BRANCH
JN   7   BRANCH
IO   8   DATA
H    9   NONE
MULC 10  MUL
DJN  11  BRANCH
MJN  12  MOVE_BRANCH
SRUN 13  FILL

Values 14 and 15 are reserved.


Formats
-------

Offsets are two's complement.  Reserved fields must be zero; a word with a
non-zero reserved field is illegal, see doc/bitcode.txt.

  31  28 27      20 19          8 7       0
 +------+----------+-------------+---------+
 |  op  | reserved                         |  NONE
 +------+----------+-------------+---------+
 |  op  | reserved | addr_offset |  data   |  DATA
 +------+----------+-------------+---------+
 |  op  |src_offset| addr_offset | factor  |  MUL
 +------+----------+-------------+---------+
 |  op  |test_offset|      jump_offset     |  BRANCH
 +------+----------+-------------+---------+
 |  op  |test_offset|         step         |  SCAN
 +------+----------+-------------+---------+
 |  op  | reserved |     move_offset       |  MOVE
 +------+----------+-------------+---------+
 |  op  |  count   | addr_offset |  data   |  FILL
 +------+----------+-------------+---------+

  31  28 27      20 19      12 11          0
 +------+----------+----------+-------------+
 |  op  |test_offset|move_offset| jump_offset|  MOVE_BRANCH
 +------+----------+----------+-------------+

Field        Bits     Range
op           [31:28]  0 to 15
src_offset   [27:20]  -128 to 127
test_offset  [27:20]  -128 to 127
addr_offset  [19:8]   -2048 to 2047
data, factor [7:0]    0 to 255
jump_offset  [19:0]   -524288 to 524287
step         [19:0]   -524288 to 524287
move_offset  [19:0]   -524288 to 524287
count        [27:20]  1 to 255, unsigned

MOVE_BRANCH only:
move_offset  [19:12]  -128 to 127
jump_offset  [11:0]   -2048 to 2047


Width rationale
---------------

[27:20] is the second memory operand and [19:8] the first, except for count in
FILL.

MJN gives up jump range to fit move_offset.  Loops that move per iteration tend
to be short, and a loop that does not fit stays M and JN.

jump_offset matches a 20-bit program counter: with a wrapping pc it reaches
every address of a 2^20-word code memory.

step and move_offset share the format of jump_offset to keep decoding uniform.
Only their low log2(MEMSIZE) bits have any effect, because base_ptr wraps.


Implementations
---------------

image.cpp (encode_bincode, decode_bincode), the C++ interpreter (brainfunk -b) and rtl/
implement this format.
rtl/ does not implement the fused instructions yet and traps on them; run it on
code from -O2 or lower.

CPU/Brainfunk.circ still implements the earlier 24-bit format, and cannot load
this output.


Program images
--------------

A program is a sequence of words, the first at pc 0.  It takes three forms, which convert into
each other without loss; brainfunk -m bit, hex and packed write them, and brainfunk -b,
visualbrainfunk -b and bfload read any of them, told apart by content:

  listing        text, a line per word: "pc:<TAB>MNEMONIC<TAB>operands", as in doc/bitcode.txt,
                 pc counting from 0.  An illegal word other than 0 lists as X with the word,
                 "X<TAB>0x9abcdef0", so that it converts back.  Spacing is free when read.
  hexadecimal    text, a line per word, eight lowercase hexadecimal digits.
  packed image   the words compressed, below.

Every word converts to a listing line and back to itself, and the same for a listing line in
the form brainfunk -m bit writes.  An instruction that does not fit its fields, which a program
that is only interpreted may have, has no word, and converting it is an error.

A packed image, as the board's loader rtl/board/loader.sv takes it:

  "BFIM"        4 bytes
  payload size  3 bytes, little endian, in bytes
  word count    3 bytes, little endian
  CRC-32        4 bytes, little endian, of the payload (the common reflected polynomial)
  payload

A packed image's payload is a run of tokens, and every multi-byte value is little endian:

  0lllllll              l + 1 literal words follow, 4 bytes each
  1lllllll, distance    l + 2 words copied from distance words back, one at a time, so a copy
                        may overlap itself.  distance is 2 bytes, from 1 to 65535.  The loader
                        reads it back from SDRAM, so any distance within what has been written
                        works.

A trailing partial line of 8 words is written to SDRAM whole, so the words after the end of an
image are undefined.  An image must end in H or an illegal word anyway, see doc/bitcode.txt.
